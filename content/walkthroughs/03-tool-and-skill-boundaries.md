# Trace a local capability

Original text walkthrough. Read one segment at a time and stop at each pause. The text below is the complete transcript and can be used as captions for your own recording. There is no required audio or video. A 5–10 minute reading-and-pause session is a provisional estimate, not a measured runtime.

## Segment 1 · Define one effect

A reading-list tool can save a local JSON list. Its success says which local artifact was written. It does not mean a book was reserved, purchased, or read.

**Pause before continuing:** Write the exact success sentence for that tool.

## Segment 2 · Distinguish empty and failed

A catalog lookup can succeed with no matching book, reject an invalid identifier, or fail because the service is unavailable. The caller needs different next actions for these outcomes.

**Pause before continuing:** Write three status examples before reading your own tool contract.

## Segment 3 · Keep procedure separate

A skill may tell an assistant how to prepare a reading list. The tool implements the write; the host selects capabilities; a discovered operation still has a bounded contract.

**Pause before continuing:** Explain which evidence would show package installation and which would show actual host use.

## Segment 4 · Test the boundary

Try malformed input, same save identity twice, and a request to buy the books. Inspect actual state as well as final prose.

**Pause before continuing:** Choose one negative case and predict the artifact state after rejection.
