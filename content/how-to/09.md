# 09 · Reuse a useful procedure with a skill

## Start here

A skill saves a procedure you want an assistant to follow again. You do not need to invent a framework or install a collection of plugins to understand it. Start with one recurring SDET task: checking whether a bug report contains enough information to reproduce the problem. Allow about 20 minutes for reading; installation is a separate choice.

If tool, instruction, and evidence still sound interchangeable, revisit [tool boundaries](../how-to/07.md) first. To find where to enter a prompt or open a local folder, use the [assistant quickstart](../../docs/ASSISTANT-QUICKSTART.md). Reading and the first prompt below need no clone or Python.

## The idea in plain language

A prompt is a request in a conversation. A skill is a folder containing a named, reusable procedure and, optionally, supporting files. Its entry file is `SKILL.md`. The short description helps the assistant decide when the procedure is relevant; the body explains how to perform it. The application running your assistant is the **host**. It decides which folders it can discover and how a skill is invoked.

For an SDET, a focused skill might inspect reproduction steps, identify missing environment details, and avoid inventing an expected result. The procedure can be reused across tickets. A skill does not make its judgments automatically correct, grant extra permissions, or prove a test ran. A one-off question rarely needs packaging: an ordinary prompt is easier when the process is still changing.

Three things must be checked separately: the files are installed correctly; the host actually loads the procedure; the resulting work follows it. Passing the first check says nothing definitive about the other two.

## A small example

Suppose a synthetic report says: “The download button did nothing. Browser: Firefox. Steps: open Reports and click Download.” A review procedure might ask for the application version, observed network response, and expected file type. It should not invent “HTTP 500” because that would make the report look complete while making it less trustworthy.

A tiny instruction-only skill could have this content:

```markdown
---
name: repro-question-helper
description: Identify missing reproduction information in synthetic bug reports.
---
Read only the report supplied by the user.
Separate facts present in the report from missing information.
Ask at most three useful follow-up questions.
Do not invent browser versions, errors, or reproduction results.
```

The lines between `---` markers are metadata: the skill's label and purpose. The remaining lines are the procedure. This example does not solve the academy's evidence-review assignment.

## Try it with Codex or Claude Code

First paste this into the conversation box of either assistant:

```text
Teach me how a reusable skill differs from a one-time prompt. Do not create
or install files yet. Use only this synthetic bug report:
“The download button did nothing. Browser: Firefox. Steps: open Reports
and click Download.”
Apply this procedure in chat: list facts supplied, then ask at most three
missing-information questions. Do not invent error codes or versions.
Explain which part of this procedure would belong in SKILL.md.
Label this as a demonstration, not evidence that a skill was installed.
```

If you want actual installation, use a new disposable workspace in a local academy copy. Ask the assistant to explain and run these commands from the academy root, stopping if the target already exists:

```sh
python3 -m lab.skill_lab install --workspace work/beginner-skill-09
python3 -m lab.skill_lab validate --workspace work/beginner-skill-09
```

This installs the existing academy package, not the tiny example above. Codex's repository location is `.agents/skills/<name>/SKILL.md`; this installer uses it. For a local Claude Code session, ask the assistant to copy the **whole** installed `signal-desk-evidence-review` folder into `.claude/skills/` inside that same disposable workspace, retaining references, assets, and scripts. Do not copy only `SKILL.md`, overwrite an existing destination, or change global configuration. These locations come from [Codex documentation](https://learn.chatgpt.com/docs/build-skills) and [Claude Code documentation](https://code.claude.com/docs/en/skills).

Start a fresh local session in **work/beginner-skill-09**, not the academy root. Open that folder as the Codex project, or use `cd work/beginner-skill-09` from the academy root and then `claude` for Claude Code. Paste this ordinary request into that session:

```text
Review the synthetic draft claims in fixtures/ticket.json against the
provided sources and save review.json. Work only inside this disposable
workspace. Do not use external connectors or network tools, install
packages, read unrelated files, or change global configuration.
Show which instructions and supporting files you actually used.
```

Inspect the resulting file and visible skill reads before asking your tutor to compare it with the fixture expectations. The expected review answer is deliberately not printed here. If automatic selection failed, record that result first. Then retry explicitly: Codex uses `$signal-desk-evidence-review`; Claude Code uses `/signal-desk-evidence-review`. Explicit success does not prove automatic selection worked.

## What you should see

The chat demonstration separates known facts from questions. The installer reports `installed_and_validated` and `host_behavior: not_tested`. That wording is correct: copying files did not call a model. A real host trial needs visible evidence of reading the installed skill and its dependencies, plus an actual output you can inspect. The academy validator checks the `.agents` installation; it does not certify Claude Code discovery of your copied `.claude` folder.

## If it goes wrong

If the workspace exists, choose a new name; do not delete someone else's practice. If the host cannot find the skill, confirm the session folder and host-specific location, then start a new session. If the output claims execution without an artifact, ask for the actual path and observable result. If model access is unavailable, stop at installation validated and leave host behavior unverified. Reading can continue.
