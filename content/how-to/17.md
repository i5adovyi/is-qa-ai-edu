# 17 · How to check whether an AI answer deserves to pass

## Start here

You do not need statistics software or programming for this lesson. You need a question, an answer, and a clear description of what a good answer should contain. If those are unfamiliar, read the [evaluation primer](../guide/04-evaluating-ai.md) first. The aim here is to recognize a weak check before trusting its score.

For an SDET, this is the difference between a test that passes and a test that actually protects a requirement. A model can produce valid JSON while making a false claim. A beautifully worded test report can claim execution that never happened. Checking the shape of an answer and checking its truth are separate jobs.

## The idea in plain language

A **grader** is whatever decides whether an output meets a requirement. It can be a small program, a person, or another AI model. A **rubric** is the set of rules that grader applies. Neither word means you need a special platform.

Use a rule-based check when the answer is exact: “Does the object contain a field named `status`?” Use evidence review when meaning matters: “Does this sentence accurately describe the supplied test result?” An AI reviewer can assist with the second job, but its verdict can also be wrong.

**Calibration** means comparing a grader's decisions with examples you have already reviewed. Suppose you deliberately include a persuasive but unsupported answer. If the grader accepts it, you have learned something about the grader, even if the rest of the answers pass. A high average score can hide a failure that matters much more than ordinary wording mistakes.

A **false acceptance** passes something that should fail. A **false rejection** fails something that should pass. Keep their denominators clear: one accepted answer among two known bad answers is 1/2, not 1 divided by every answer in the collection. With a small collection, report the actual counts. You do not need confidence intervals to understand four examples, and four examples cannot establish broad reliability.

## A small example

Here is an invented Signal Desk test result:

```text
Run R-31: test_password_reset timed out before its assertion.
No result exists for the rerun.
```

Compare two summaries:

```text
A: Password reset passed after a rerun.
B: Password reset remains unverified: the recorded attempt timed out.
```

The rubric is “Describe only recorded execution; identify missing evidence.” A passes a spelling or grammar check, but fails the rubric because the successful rerun is invented. B meets the rubric. This example teaches the checking method; it is not a solution to the retained lesson's calibration assignment.

Notice that the rubric does not require one exact sentence. “There is no verified pass yet” could also be acceptable. Exact text matching would reject useful wording for the wrong reason.

## Try it with Codex or Claude Code

1. Open a conversation in either assistant. You can paste this without cloning the academy. If you want the project files available, follow the [assistant quickstart](../../docs/ASSISTANT-QUICKSTART.md).
2. Paste the prompt below. It provides all the evidence the assistant needs.

```text
Teach me how to review an AI-generated test summary. Do not edit files,
run commands, or solve any academy exercise. Use only this synthetic data:
Run R-31: test_password_reset timed out before its assertion.
There is no recorded rerun.
Candidate A: Password reset passed after a rerun.
Candidate B: Password reset remains unverified because the attempt timed out.
Rubric: describe only recorded execution and identify missing evidence.
For each candidate, give a verdict and quote the specific evidence or gap.
Then show one wording variation that should preserve the verdict.
Explain what a simple format check could and could not verify.
Keep your response under 250 words and explain unfamiliar terms.
```

3. Compare each verdict with the two source lines yourself. The assistant's agreement is feedback, not independent execution evidence.
4. Ask: “Which part of your checking was a judgment, and which part could a small program check exactly?”
5. Stop when you can explain that distinction in your own words. Saving a document or building a grading service is unnecessary.

## What you should see

The assistant should reject A's invented pass and accept B's bounded conclusion. It should cite the missing rerun, not claim it looked at real logs. The wording variation should preserve the factual claim rather than introducing new results.

You have completed a guided demonstration of a rubric, not an evaluation of the assistant over many cases. A second opinion from the same assistant is still related to the first; do not describe it as an independent human review.

## If it goes wrong

If both candidates pass, ask it to point to the evidence for the rerun. If it grades tone instead of correctness, repeat the rubric and ask for one verdict per requirement. If it invents a precise “confidence” percentage, ask what measured data supports that number. If you disagree about wording, clarify the rule before scoring more examples; changing the rule silently makes comparisons misleading.
